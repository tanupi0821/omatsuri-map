# まつりマップ（関東）

大手イベントサイトが拾わない **町内会・自治会レベルの盆踊りや夏祭り** を、出典つきで全部載せるサイト。
関東 1 都 6 県を収録。構成は最初から全国展開できる形にしてある。

## 使い方

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

`build` は先に `scripts/validate.mjs` を走らせる。出典や最終確認日が欠けたデータがあると
ビルドが落ちるので、裏の取れていない情報は公開されない。

収集を全部流し直すとき（import → enrich → validate）:

```bash
npm run collect
```

`import` は「まとめサイトから広く集める」、`enrich` は「一次情報で裏を取って上書きする」。
import は既存ファイルを上書きしないが、enrich は意図的に上書きする（出典の格を上げる操作だから）。

## 構成

```
data/
  areas/kanagawa-kawasaki.yml          川崎市のエリア定義＋区ごとの一次情報源
  areas/kanagawa-yokohama.yml          横浜市のエリア定義＋情報源
  festivals/<pref>/<city>/<ward>/*.yml 1 祭り 1 ファイル
scripts/
  validate.mjs                         データ検証（build 前に必ず実行）
  import-all.mjs                       インポーターを全部流す
  enrich-all.mjs                       一次情報での裏取りを全部流す
  import/_lib.mjs                      共通処理（emit=新規追加 / patch=上書き）
  import/*.mjs                         出典ごとのインポーター
  enrich/*.mjs                         一次情報で既存データを上書きするスクリプト
src/
  lib/data.js                          YAML 読み込みと表示用フォーマット
  pages/index.astro                    一覧
  pages/f/[id].astro                   個別ページ
docs/schema.md                         データスキーマと掲載ルール
```

DB は使わない。データは Git 上の YAML なので、差分がレビューでき、壊れても戻せて、
将来ユーザーからの情報提供を PR として受けられる。数万件までこの構成で足りる。

## データを増やすとき

1. `data/areas/*.yml` にその区の情報源を追記する
2. 情報源ごとに `scripts/import/` へインポーターを書く（`_lib.mjs` の `emit()` に配列を渡すだけ）
3. `npm run validate` を通す
4. `npm run build` で確認して公開

インポーターは既存ファイルを上書きしないので、手で書いた紹介文や緯度経度は消えない。
出典元の更新を取り込み直したいときだけ `--force`。

### 掲載ルール（守る）

- 扱うのは **日時・場所・主催という事実情報だけ**。紹介文は自分の言葉で書き、出典の文章は写さない
- 出典 URL のない情報は載せない（validate で落ちる）
- 出典元の robots.txt と利用規約に従う。情報源には必ずリンクを張る
- 公開告知されている祭りだけを対象にする。個人宅・私有地の集まりは載せない
- 去年の日程を今年のものとして出さない。当年の開催回がなければ「今年は未確認」と明示する
- **「例年8月上旬」しか出ていないものは入れない**。日付が確定しているものだけを載せる

## 一次情報まで遡ると何が起きるか

まとめサイトで見つけた祭りを、神社・町内会・実行委員会の公式サイトまで遡って裏を取る作業
（`scripts/enrich/`）で実際に出てきたもの。

- **川崎山王祭が2026年から6月開催に変わっていた。** まとめサイト経由で入れた 8/1〜8/3 は
  前年までの日程で、完全な誤情報だった。稲毛神社の公式ページで発覚。猛暑を避けて氏子の負担を
  減らすため 8月→6月 に移したとのこと。**まとめサイトだけを見ていたら気づけない類の誤り。**
- **花の台町内会（宮前区）の盆踊りは 8/2 が雷雨予報で中止**になっていた。町内会の公式サイトに
  告知が出ていた。まとめサイトは中止まで追わない。
- **「関内まつり」は厳島神社の例大祭ではなかった。** 関内地区連合町内会が主催するまちの祭りで、
  厳島神社の例祭日は別途 8月1日。まとめサイトの「関内まつり（厳島神社例大祭）」という表記は不正確。
- **神奈川県神社庁が県内全神社の例祭日をルールの形で公開している。** 横浜市776社・川崎市266社。
  「10月第1日曜日」「9月15日に近い日曜日」といった形なので、今年の日程が未発表でも
  「毎年いつごろか」は出せる。まとめサイトが一切扱わない秋の例大祭や冬の神事もここから拾える。
  これで幸区（それまで1件）と高津区の秋祭りが埋まった。
- **金沢区は区の行事カレンダーが宵宮と本祭を分けて時間まで出していた。** 観光協会のページより
  はるかに詳しく、通年の行事も載っている。

## 情報源の実情

**町内会レベルのデータが取れるかは「その市区に密着した誰かが手で集めているか」で決まる。**
神社庁でも全国規模のまとめサイトでもない。運営主体は区役所・地域情報サイト・区議の個人サイトと
バラバラで、横断的な入口は存在しない。市区ごとに個別に探すしかない。

| 市区 | 媒体の運営主体 | 件数 |
|---|---|---:|
| 東京都足立区 | 区役所 | 105 |
| 東京都江戸川区 | 区役所 | 101 |
| 東京都江東区 | 地域情報サイト | 71 |
| 東京都板橋区 | 地域情報サイト（PDF） | 66 |
| 東京都葛飾区 | 区役所（PDF） | 52 |
| 東京都練馬区 | 区議の個人サイト | 28 |
| 東京都世田谷区 | 地域情報サイト | 26 |
| 川崎市宮前区 | 区役所 | 25 |
| さいたま市 | 地域情報サイト | 24 |
| 千葉県船橋市 | まいぷれ船橋 | 13 |
| 埼玉県川口市 | 地域情報サイト | 8 |

一方、**神社の例大祭は県神社庁から機械的に取れる**。ただし神社庁が神社データベースを
持っているのは調べた範囲で神奈川・東京・埼玉のみ。千葉・群馬は神社庁に神社DBが無く、
茨城・栃木はサイトマップも無い。この 4 県は市を代表する祭りしか拾えていない。

詳細は [docs/kanto-plan.md](docs/kanto-plan.md)。
