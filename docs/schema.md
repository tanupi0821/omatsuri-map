# データスキーマ

1 祭り = 1 YAML ファイル。置き場所は `data/festivals/<pref>/<city>/<ward>/<id>.yml`。

全国展開してもこの階層が深くなるだけで、コードは変えない。

## festival（不変の情報）

| フィールド | 必須 | 説明 |
|---|---|---|
| `id` | ○ | 全国で一意。`<ward>-<場所や主催>-<種別>` のローマ字。ファイル名と一致させる |
| `name` | ○ | 正式名称。無名の町内会盆踊りは「〇〇町内会 盆踊り」とする |
| `kind` | ○ | `盆踊り` / `夏祭り` / `納涼祭` / `例大祭` / `秋祭り` / `春祭り` / `区民祭` / `こどもまつり` / `商店街` / `花火` / `縁日` / `神事` |
| `scale` | ○ | `町内会` / `地区` / `区` / `市` — 大手サイトが拾わないのは `町内会` と `地区` |
| `area.pref` `area.city` `area.ward` | ○ | 行政区分 |
| `venue.name` | ○ | 会場名 |
| `venue.address` | | 住所。ジオコーディングの入力になる |
| `venue.lat` `venue.lng` | | 緯度経度。未取得なら `null` |
| `station` | | 最寄駅（出典に書かれている場合のみ） |
| `recurrence` | | 例祭日の決まり（例: `10月第1日曜日`）。神社庁や神社公式が公開しているルール。**今年の日程が未発表でもこれがあれば役に立つ** |
| `recurrence_source` | | `recurrence` の出典 URL |
| `organizer` | | 主催（町内会・自治会・神社など） |
| `shrine` | | 例大祭の場合の神社名 |
| `stalls` | | **屋台・露店が出るか**。`yes` / `no` / `unknown`（既定）。おでかけ先を探す人にとって決定的な情報なので独立した項目にしている |
| `tags` | | `子ども向け` `花火` `神輿` `山車` `雨天決行` など |
| `photos` | | 写真。`{url, width, height, credit, license, license_url, source}` の配列。**再利用が許諾された画像だけ**（後述） |
| `description` | | 自分の言葉で書く。**出典サイトの文章はコピーしない** |
| `links` | | 主催者・神社の公式ページ |

## occurrences[]（年ごとの開催回）

祭りは年次イベントで、日程は毎年変わる。**去年の日程を今年のものとして出さない**ためにマスタと分離している。

| フィールド | 必須 | 説明 |
|---|---|---|
| `year` | ○ | 開催年 |
| `dates` | ○ | `YYYY-MM-DD` の配列。2日開催なら 2 要素 |
| `date_note` | | 日付が確定していないときの表記（例: `9月または10月`） |
| `start_time` `end_time` | | `HH:MM` |
| `status` | ○ | `confirmed` 公式発表済 / `estimated` 例年からの推定 / `unconfirmed` 未確認 / `cancelled` 中止 / `postponed` 延期 |
| `source_url` | ○ | **出典。これがない情報は載せない** |
| `source_name` | | 出典の名前（宮前区役所、など） |
| `source_type` | | 出典の格。`official`（神社・主催者の公式発表）> `gov`（行政）> `media`（地域メディア）> `aggregator`（まとめサイト）。まとめサイトで見つけた祭りは、必ず一次情報まで遡って `official` に格上げしていく |
| `checked_at` | ○ | `YYYY-MM-DD`。最終確認日。古くなったら UI で警告を出す |
| `note` | | 中止理由、会場変更など |

## 屋台・露店の有無（`stalls`）

**同じ神社でも祭りによって性格がまったく違う。** 例えば馬絹神社（川崎市宮前区）は
7月の夏季大祭が神事中心なのに対し、10月の秋季例大祭は神輿が地区を巡行し多くの露店が出る。
「祭りに行こう」と思って調べる人にとっては、この差が最も知りたいことになる。

- `yes` — 屋台・露店・夜店が出ることを出典で確認した
- `no` — 神事のみで露店は出ないことを確認した
- `unknown` — 未確認（既定値）

**神社庁から一括で取り込んだ例大祭は、例祭日しか分からないので原則 `unknown`。**
`unknown` を `yes` のように見せないこと。一覧では「屋台あり」で絞り込めるようにし、
確認できたものだけがそこに出る。

新しく神社の祭りを足すときは、**まず露店の有無を調べ、確認できたものを `yes` で入れる**。
調べずに入れる場合は `unknown` のままにする。

### 「屋台」という語に注意

日本語の「屋台」には二つの意味がある。

1. 食べ物や遊びを売る**露店・夜店**（`stalls` が指すのはこちら）
2. 祭りで曳く**山車**。とくに栃木・群馬・埼玉北部で「屋台行事」「屋台まつり」と呼ぶ

鹿沼今宮神社祭の**屋台行事**はユネスコ無形文化遺産の山車行事であって露店の話ではない。
出典に「屋台」とあっても、どちらの意味かを確かめてから `stalls` を立てること。
山車のほうは `tags` に `山車` として入れる。

## 写真（`photos`）

祭りの雰囲気は文字だけでは伝わらないので写真を出す。ただし**他サイトの画像を勝手に
持ってくることはしない**。著作権の問題であると同時に、相手のサーバに負担をかける行為でもある。

使えるのは次のものだけ。

1. **ウィキメディア・コモンズ**の CC ライセンス画像（要 著作者表示）
2. 自治体・観光協会が**再利用可**と明記して配布している素材
3. 主催者から直接許諾を得たもの
4. 自分で撮ったもの

各写真に `credit`（著作者）、`license`（CC BY-SA 4.0 など）、`license_url`、
`source`（画像の説明ページ）を必ず持たせ、**画像の下に表示する**。
表示できない情報しかない画像は載せない。

画像ファイルは自前で持たず、コモンズの URL を参照する。
コモンズは再利用を前提に運用されていて、ホットリンクも許容されている。

```yaml
photos:
  - url: https://upload.wikimedia.org/.../800px-Awa-odori.jpg
    width: 800
    height: 533
    credit: ajari from Japan
    license: CC BY 2.0
    license_url: https://creativecommons.org/licenses/by/2.0
    source: https://commons.wikimedia.org/wiki/File:Awa-odori_K%C5%8Denji_03.jpg
```

## 表示ルール（信頼性の根幹）

- 個別ページには必ず **出典リンクと最終確認日** を出す。
- `status` が `confirmed` 以外のときは「未確定」バッジを出し、断定した書き方をしない。
- 当年の開催回が無い祭りは「例年◯月ごろ／今年の情報は未確認」と表示する。過去の日程を今年として出すのは禁止。
- 個人宅・私有地でひっそりやっている集まりは載せない。**公開告知されているものだけ**を対象にする。

## 収集時の原則

- 扱うのは日時・場所・主催といった事実情報のみ。紹介文は自分で書く。
- 出典サイトの robots.txt と利用規約に従う。
- 情報源には必ずリンクを張る（相手にとっても不利益にならない形にする）。

## paid_seats（有料観覧席の有無）

`yes` / `no` / `unknown`。**花火大会にだけ書く。**

構造化データの `isAccessibleForFree`（入場無料）は、町内会の盆踊りや神社の例祭では
断定してよいが、**花火大会は有料観覧席があるので言い切れない**。
`no`（有料席は無い）と確認できたものだけ「無料」と申告し、
`yes` と `unknown` は黙る（確かめていないことを断定しない）。

`paid_seats_note` に、席種・料金・販売時期などの補足を書いてよい。
出典は `occurrences[].source_url` か `links` に残すこと。
