# 関東全域への拡大 — 作業計画と進捗

## 屋台・露店の有無をどう集めるか

利用者にとって決定的なのは「屋台が出るか」。集められる入口は限られている。

| 入口 | 使えるもの |
|---|---|
| **花火大会DB**（`hanabi.walkerplus.com/list/<県>/yatai/`） | **屋台の有無を項目として持つ。北関東で唯一まとまって取れる** |
| 夏祭りDB（`summer.walkerplus.com/odekake/list/<県>/sg0999/yatai/`） | 同上。夏祭りのみ |
| 行政一覧の備考欄 | 葛飾区の PDF は「模擬店あり（ラムネ、かき氷…）」まで書いてある |
| 神社の例大祭 | **まず公開されていない**。個別に調べるしかない |

**「屋台」が山車を指す地域がある**（栃木・群馬・埼玉北部の「屋台行事」）。
出典に屋台とあっても意味を確かめること。詳細は `docs/schema.md`。

## 写真

ウィキメディア・コモンズの CC ライセンス画像だけを使う。他サイトの画像は持ってこない。

```bash
node scripts/crawl/commons-photos.mjs --min-scale 市
```

```bash
node scripts/enrich/photos.mjs
```

- ライセンス・著作者・出典ページが揃っていないものは validate で落ちる
- NonCommercial / NoDerivatives は除外
- 祭りの名前から固有語（地名・神社名）を取り出し、画像の題名・説明・カテゴリに
  その語が出るものだけ採用する。これをしないと「かまがやの花火」に
  1875年生まれの人物写真が当たるような誤爆が起きる
- **八幡神社・稲荷神社・諏訪神社のようなありふれた社号は固有語にならない**。
  厚木市の八幡神社に蒲郡市の三谷八幡神社の写真が付いた。これらは
  市区町村名の一致を伴って初めて採用する（`COMMON_SHRINE`）
- **同じ写真が 2 つ以上の祭りに付いていたら、どちらにも付けない**。
  一般的すぎる証拠で、その祭りを指していない
- **神社の祭りは市区町村名か鎮座地の町名の裏づけを必須にする**。社号は全国で
  重複するので、社号の一致だけでは同名の別社をつかむ。大田区の三輪神社に岐阜の
  揖斐祭、新宿の赤城神社に群馬の赤城大沼の写真が付いた。コモンズの題名は
  ローマ字のことも多いので、市区町村の slug も地名の錨に足す
- 「このデータで 1 社しか無い社号なら通す」も試したが**駄目**。
  一意なのはこのデータの中だけで、日本全国では違う（榛名神社・赤城神社）
- 判定に使った材料（説明・カテゴリ）は残しておくこと。題名しか残していなかったので、
  後から見直したとき正しい写真まで落とした。`scripts/crawl/commons-meta.mjs` で取り直す
- **説明に別の土地の名前が出ていたら外す**。札幌の狸まつりに「阿波の狸まつり（徳島）」、
  大阪の天神祭に「伊賀市だんじり会館（三重）」の写真が付いた
- ただし**県境の花火大会は両岸の市が共催する**（市川市民納涼花火大会は江戸川区と、
  関門海峡花火大会は下関市と門司区）。自分の土地の名前が出ていれば他県が出ていてもよい
- 市区町村名で照合するときは**実在の市区町村に限る**。素朴に「◯◯市」を拾うと
  「サギ草市」「錦糸町」を市区町村だと思ってしまう
- 「祭りを写した写真か」も見る。ただし**祭り会場で撮った物の写真は残す**
  （豊田おいでんまつりのピザ屋の車は、その祭りの屋台なので誤りではない）
- **「桜まつり」「駅前夏祭り」「天王祭」「summer festival」のように
  祭りの種類しか言っていない名前**も、神社の祭りと同じく地名の裏づけを要る。
  袋井市の「summer festival」にイタリアの音楽祭、東久留米市の「天王祭」に
  品川の荏原神社の写真が付いた。この規則で京都の祇園祭も巻き添えで落ちるが、
  **間違った写真を残すより取りこぼす方を選ぶ**
- 重複した祭りを先にまとめること。同じ写真が 2 件に付くと両方から外れる
  （「入谷朝顔まつり」と「入谷朝顔まつり(入谷朝顔市)」が半角括弧の違いで
  別物として残っていた）
- Wikimedia の API はレート制限が厳しい。2 秒あけ、429 は Retry-After に従って待つ

判定を厳しくしたら、過去に採った分も同じ物差しで測り直す:

```bash
node scripts/enrich/photos-audit.mjs
```

`--apply` を付けるまで外す候補を並べるだけ。

## 全国展開

関東で神社庁を舐めきったあと、他府県には同種の神社DBがほぼ無い
（愛知はJS描画、大阪・福岡・広島は接続不可、京都・兵庫・静岡・新潟・長野は404）。
代わりに**ウォーカープラスの2つのDBが47都道府県を同じURL規則で持ち、
しかも屋台の有無で絞り込める**。「露店があるものだけ載せる」方針のまま広げられる。

| 入口 | URL | JSON-LD の形 |
|---|---|---|
| 花火 | `hanabi.walkerplus.com/list/<ar>/yatai/` | `WebPage → mainEntity(ItemList) → itemListElement[].item` |
| 夏祭り・盆踊り | `summer.walkerplus.com/odekake/list/<ar>/sg0999/yatai/` | **Event の配列**（1ページ10件） |

`ar` コードは `scripts/lib/prefs.mjs`。HTML の class を追うより構造化データが正確。

**1.2 秒間隔で 47 都道府県を続けて叩いたら 2 県目以降が全部 404 になった。**
本物の 404 ではなく出しすぎの遮断で、時間を空けると 200 が返る。3 秒あける。
なお 2 ページ目以降の 404 は単に最終ページを越えただけなので、待ち直さない。

## 重複

全国のまとめサイトを入れたら、関東で一次情報から入れていた祭りと重なった
（手賀沼花火大会が 2 件など）。

```bash
node scripts/dedupe.mjs        # --apply で実行
```

**同じ市に同じ名前の祭りが複数あるのは普通のこと**なので、名前一致だけで
まとめてはいけない。平塚市には八坂神社例祭が 3 つあり、東八幡・飯島・纒の
別々の神社の祭り。そこで**まとめサイト由来を含む組だけ**を対象にする。
実際、対象 44 組に例祭型は 1 つも無く、非対象 93 組は全て住所の違う別の神社だった。

残す方は出典の質で決め（公式 > 行政 > メディア > まとめ）、消す方が持っていた
屋台の有無・写真・日付・出典リンクは残す方に移す。

## 埼玉神社庁の「お祭り」欄は書き方が 2 通りある

```
(a) ５月３日 例祭 10月15日 神嘗祭      … 日付 → 祭名
(b) 夏祭（７月２０日）、例大祭（１１月３日） … 祭名（日付）
```

(b) を (a) の規則で読むと、**日付に次の祭名が付き、名前も括弧ごと壊れる**。
「）、例大祭（」という名前の祭りが 21 件出来ていた。しかも最初の祭りの名前が
消えるので、日付と祭名の対応が 1 つずつずれる（八幡大神社の７月２０日は
例大祭ではなく天王祭だった）。(b) を先に試すよう直し、52 社を取り直した。

## 出典が中止・去年の日程のまま、ということがある

まとめサイトの一覧には、**名前に「【2026年中止】」と書かれたまま**の項目が
13 件あった（海の日名古屋みなと祭花火大会など）。名前で弾く。

前年の日程のまま更新されていない項目も 102 件ある。こちらは消さずに、
`occurrences[].note` に「出典は2025年の日程のまま。2026年の開催は発表されていない」
と書いて載せる。**日付が今年のものだと誤解させないこと**が要点。

## まいぷれ（地域情報サイト）

`robots.txt` が **Crawl-delay: 90** を宣言している。必ず 90 秒あけること。

```bash
node scripts/crawl/mypl.mjs suginami   # 90 秒間隔で取得
node scripts/import/mypl.mjs suginami
```

記事本文が「月 / イベント名 / 会場 / 開催日 / 時間」の表なので、表の行として読む。
杉並区で 13 件（うち屋台の明記 3 件）。ただし**記事の URL は地域版ごとに違い**、
`summer-fes_<area>` が通ったのは杉並だけ。越谷・所沢は 404。一括では取れない。

## 号外NET — 町内会レベルが全国で取れる唯一の入口

**地域版が 284 ある**（北関東や地方都市も含む）。しかも WordPress の REST API が
開いていて検索語つきで記事を引ける。

```bash
node scripts/crawl/goguynet.mjs      # 285地域 × 5語、1.5秒間隔
node scripts/import/goguynet.mjs
```

記事の本文が決まった形をしている:

```
～納涼盆踊り～ 日時 2026年8月1日（土）16時～21時 場所 都立汐入公園噴水広場周辺
```

- 市区町村は**題名の【】**から取る（地域版が複数市をまとめていることがあるため）
- 見出しが「青森県・岩手県・宮城県」のように複数県のことがある。市名で引き、
  候補が複数なら見出しの県で絞る
- 政令市の区も題名に出る（「【中原区】…」）ので区としても引けるようにする
- **「場所」は地の文にも出る**。「場所には多数の売店も出店予定となっており…」を
  会場にしてしまった。助詞・文末表現で始まるものは捨て、「◯◯で開催」から拾うときは
  公園・神社・小学校など**場所らしい語で終わるもの**に限る
  （「全体が一体感に包まれる」を会場にしていた）
- 「雨天の場合は8月2日に順延」の予備日を開催日にしない
- **「日時」という欄があるのは一部だけ**。多くは地の文で
  「2026年7月31日（金）から8月2日（日）まで開催されます」と書く。
  欄が無いという理由で捨てたら 377 件落ちていた。地の文から拾うときは
  本文の頭 400 字に限る（後半には「昨年は…」の日付が出る）
- 名前は「東山温泉盆踊り2026」のように**鉤括弧**で括られることが多い
- 題名の【】には「2026年最新」のような市区町村でないものも入る。
  そのまま登録すると「号外NET（2026年最新）」というエリアができる
- **同じ祭りを複数回記事にする**（告知と当日レポート）。dedupe の対象に含める
- 「夏祭り」だけの総称や「午後9時 ・花火大会 午後7時30分」のような
  抜き出し損ねは、どの祭りか分からないので捨てる
- 店舗の集客企画（「夏祭りファミリーDay」等）は地域の祭りではないので除く
- **名前は題名の鉤括弧を先に見る**。地の文から切り出すと
  「多くの人で賑わう「八坂神社祭」のように途中で切れる（正しくは八坂神社祭礼）
- 鉤括弧の中が「夏祭り」だけのことがある。直前の主催者・会場を前に付ける
  （「紅葉八幡宮で「夏祭り」開催へ」→ 紅葉八幡宮 夏祭り）
- 検索語は 5 語では足りず、12 語に増やした（秋祭り・祭礼・夜店・盆おどりなど）。
  取得済みの語は飛ばして足りない分だけ引く（全部取り直すと 85 分かかる）

## レアリア（rarea.events）

神奈川・東京中心の地域イベント媒体。号外NET と同じく WordPress の REST API が開いている。
**自治会・町内会が主催する祭り**を、縁日ブースやキッチンカーの記述つきで書く。

```bash
node scripts/crawl/rarea.mjs
node scripts/import/rarea.mjs
```

題名に日付と市区町村が素で入る（【】ではない）:

```
2026年8月15日　厚木市　森の里若宮公園で夏祭り
…8月16日は「富士見公園夏まつり」＠川崎市川崎区
```

市区町村は**既に定義してある名前だけを拾う**。素朴に「◯◯市」を拾うと
祭りの名前の一部を市だと思ってしまう。政令市の区を先に見る
（「川崎市川崎区」が「川崎市」より先に当たるように長い名前から順に）。

3月以降の記事に絞ると 72 件。号外NET より小さいが粒度は同じ。

## 東京フェスタ（tokyofesta.com）

東京の祭り専門の媒体。WordPress の REST API が開いている。
書き方が号外NET・レアリアより整っていて、本文が箇条書き:

```
日時：2026年8月28日(金)〜29日(土) 18:30～20:30
会場：京橋中央ひろば（ガレリア）
主催：京橋一の部連合町会
```

**主催が町会名で書かれている**ので、町内会の祭りかどうかを規模の判定に使える。

```bash
node scripts/crawl/tokyofesta.mjs
node scripts/import/tokyofesta.mjs
```

- 「日時：」の**全角コロン**に対応が要る（`pickDates`）
- 主催の抽出で「主催：Park」「主催：BUBBLE」と本文の英語部分を拾っていた。
  団体名なら日本語が入るので、それを条件にする
- **記事に区名が出ず、街の名前だけのことが多い**（「渋谷キャスト」「巣鴨駅南口」
  「自由が丘駅前」）。よく出る街を区に対応づける表を持つ。
  これで市区町村不明が 50 → 26 件に減り、取り込みが 39 → 57 件になった
- 「絶品グルメ☆ビール＆日本酒祭り＠神田明神納涼祭り」のように
  記号でつないだ前半が煽り文句。`＠` の後ろが本題
- **東京フェスタは 23 区だけの媒体ではない**。武蔵野・立川・府中・稲城も出る。
  エリア定義に無い市は `citySlug` が引けるものだけ足す
- **都外の祭りも少し載る**（横浜・川越・所沢・柏の葉・江の島）。
  全国のエリア定義で当てにいくと同名の市で誤判定した:
  「しながわスネークタウン（蛇窪神社）」→ 神奈川県大井町、
  「すもも祭（府中市・大國魂神社）」→ 広島県府中市、
  「新潟フェス in 東急歌舞伎町タワー」→ 新潟県長岡市。
  **この媒体は東京都に限る**。都外は他の媒体で拾う
- **題名がそのまま祭りの名前**。本文は時刻表なので、そちらから拾うと
  「21:00 （盆踊り大会17:00」のような切れ端になる。題名を先に使う。
  なお**号外NETの題名は文章**（「【荒川区】8月22日（土）、…が開催されます！」）
  なので、この直し方は東京フェスタにしか効かない
- 「盆踊りエリア」「おまつり広場」は会場の区分であって祭りの名前ではない。
  **会場名を祭り名にすると写真も引きずられる**（八戸市の「おまつり広場」に
  「仙台七夕まつり おまつり広場」の写真が付いた）

## 政令市の区が町会レベルの一覧を作っている

東京の足立区・江戸川区・葛飾区と同じ型が、**大阪市・名古屋市**にもあった。
名古屋は区ではなく**学区**単位。

```bash
node scripts/crawl/city-ward.mjs
node scripts/import/city-ward.mjs
```

**列の並びが区ごとに違う**:

```
西淀川区: 地域 / 名称 / 開催日 / 場所
此花区:   行事 / 日時 / 場所
名東区:   行事名 / 日にち / 時間 / 場所
```

列の数で決め打ちすると名東区で「日にち」を場所だと思ってしまう。
**見出し行から列の意味を読む**こと（`roleOf`）。

- ページの URL は区ごとにばらばらで規則から導けない。`PAGES` に足していく
- 「8月14日(金曜日)、8月15日(土曜日)」のように複数日のことがあるので全部拾う
- **「予備日7月5日」は雨天時の日程**なので開催日ではない
- 名前に付く「※」は注記の印
- 「酉島夜店と花火大会」のように名前や日時欄に夜店とあれば屋台は確定できる

現在: 西淀川区 22 / 此花区 8 / 名東区 15 ＝ **45 件**。

調べたが表になっていなかったもの: 大阪市旭区（PDF だが画像）、
大阪市城東区・東住吉区（地域名の一覧のみで日程が無い）、
名古屋市緑区（表が無い）、名古屋市昭和区（表はあるが防災訓練の種目表）。

**札幌市には無い**。「◯◯区どさんこプレス」型の媒体は東区だけで、
他区の subdomain（chuoku / kitaku / shiroishi / toyohira / teine / nishiku /
minamiku / atsubetsu / kiyota）はいずれも存在しない。

## 「◯◯フェスタ」型の祭り専門メディアは東京だけ

osakafesta / nagoyafesta / fukuokafesta / sapporofesta / kansaifesta /
matsurifesta はいずれも存在しない。東京フェスタは例外的な媒体。

## 記事から祭りを取り出す処理は共通化した

`scripts/import/_article.mjs`。号外NET とレアリアで同じ癖に当たるため。
**ここの条件はすべて実データで誤りを見つけて足したもの**。消すときは再発しないか確かめる。

- **送り仮名の無い「祭」**で終わる名前がある（万灯みたま祭・吉原祇園祭・妙見大祭）。
  `IS_FESTIVAL` に入れないと神社の祭りがまとめて落ちる
- 「2026年胡録神社例大祭」の年は名前ではない。残すと「日付が混ざっている」として
  落としてしまい、荒川区の主要な祭りが消える
- 会場に「９月26日・27日に美しが丘公園」と日付が前置されることがある
- 題名から名前を切り出す最後の手段は文を拾いやすい。
  「龍城ケ丘自治会が初の夏まつり」「川崎港で夏の納涼祭」は名前ではない
- キッチンカー・縁日ブースも屋台のうち
- **祭りの名前は題名の終わりの方に置かれる**。候補が複数あれば後ろを採る
  （「子供みこしや提灯山笠が…♪ 7月14日 二日市八幡宮夏季大祭」）
- 「2026まちなか夏祭り」のように年だけ前置される。年を落としてから判定しないと
  「日付が混ざっている」として捨ててしまう
- 「夏はホークス！天神夏まつり2026」の煽り文句は落とす（感嘆符の後ろが本題）
- 「今年は覚王山夏祭」の頭の言葉も名前ではない
- 呼びかけ文をそのまま名前にしない（「今年は蒲郡花火大会へ行こう！」
  「レシートを集めて夏まつり」「祭りが始まるぞー！」）
- 総称の前に付ける主催者・会場は、鉤括弧から離れていることがある
  （「我孫子市民プラザで、7月25日(土)に「夏まつり」が開催」）
- **九州の媒体は「令和8年7月25日」と和暦で書く**。読めないとその地域が
  まるごと落ちる。全角数字も混在する（「6月６日（土）」）
- 「7月24日・25日」「7月27日と28日」のように 2 日目以降の月が省かれる。
  月を補ってから読む
- 年が書かれていないときは**記事の掲載年**を既定にする。本文に出てくる年を
  拾うと回顧の文（「2025年は…」）の年を付けてしまい、去年の日付が混ざる
- 名前に時刻が混ざることがある（「祭典 17:00過ぎ」「盆踊り：18:00」）。
  本文の時刻表から切り出したもの
- 「7月30日は美奈宜神社で夏越祭」のように**日付が前に付く**題名がある。
  日付を落としてから名前を切り出す
- 「◯◯で△△祭」の△△だけを採る案は**駄目**。△△が総称のときに
  「川崎港で夏の納涼祭」→「夏の納涼祭」となって悪化する

## 記事から屋台の有無を埋める

```bash
node scripts/enrich/stalls-from-articles.mjs   # --apply で実行
```

号外NET・レアリアの記事 1500 件のうち、祭りとして取り込めたのは一部。
残りにも**既にある祭りの屋台の記述**が入っている。神社の例祭は神社庁からは
屋台の有無が分からないので、ここで埋められると大きい。

誤って yes にしないための条件:

- 記事の市区町村が一致すること
- **題名に名前が出ていること**。本文のどこかに出ているだけだと、別の祭りの記事で
  言及されただけのものを拾う（石濱神社納涼大会の記事で諏方神社を yes にしていた）
- 社号だけの一致は使わない（「八幡神社」では同名の別社をつかむ）
- **同じ神社に祭りが複数あるときは上げない**。白旗神社（藤沢市）には例祭・
  どんど祭・秋祭があり、7 月の白旗まつりの記事で 3 つとも yes にしていた。
  同じ神社でも祭りが違えば屋台の有無は違う（馬絹神社の 7 月は神事のみ、
  10 月は露店が多い）

**同じ神社に複数あっても、日付が合えばどの祭りか決まる**。記事の 845 件中
800 件に日付があるので、月日の一致を条件に足した。これで白旗神社（藤沢市）の
例祭だけを正しく上げられる。

ありふれた社号でも**鎮座地の町名**を伴えば一意になる（「厚木市及川」の八幡神社）。
条件には入れたが、題名に町名と社号が両方出る記事は無く、増えなかった。

## 名前の揺れで結びつかない分を拾う

```bash

```

`dedupe.mjs` は正規化して**完全一致**でまとめるので、書き方が違うと残る。


こちらは**どちらかがどちらかを含む**まで許して、屋台の有無だけを写す。
祭りそのものはまとめない（別の祭りだった場合の被害が大きい）。**33 件**。

## サイトの構成（2026-08-05 に作り直した）

**トップに全件を並べていたら 2.9MB になっていた。** 携帯で開ける大きさではない。
地域でページを割り、それぞれが扱う件数を絞った。

| URL | 中身 | 大きさ |
|---|---|---:|
| `/` | 都道府県の入口＋これから開催の 120 件 | 101KB |
| `/a/<県>/` | 市区町村の入口＋これから開催の 150 件 | 105〜114KB |
| `/a/<県>/<市>/` | その市区町村の全件 | 最大 174KB |
| `/f/<id>` | 祭りの詳細 | — |

  詳細ページより**エリアのページを優先**して巡回してもらう

### 絞り込み

一覧の部品は次で絞れる。すべてブラウザ側で、ページ遷移なし。

| 手段 | 備考 |
|---|---|
| 期間（これから／今週末／すべて） | 既定は「これから」。今週末は金土日 |
| 種別 | そのページに実在する種別だけ出す |
| 月 | 開催のある月だけ出す。**月を選んだら期間を「すべて」に切り替える**（過ぎた月で 0 件になるため） |
| 屋台あり | 確認できたものだけ。未確認は出さない |
| 名前・会場・町会名で検索 | 20 件を超えるページだけ。空白区切りの AND |

検索の対象は名前・会場・主催・神社・市区町村。町内会の祭りは
「◯◯町会」「◯◯公園」で探されるので、その両方に当たるようにしてある。

都道府県の並びは**地理順（北から南）**。件数順だと東京・神奈川が先頭に来て、
自分の県を目で追えない。`scripts/lib/prefs.mjs` の順をそのまま使う。

### 回遊と共有

- 詳細ページに**同じ市区町村の他の祭り**を 8 件出す。これが無いと詳細ページが
  行き止まりになる。これから開催のものを先に、日付の近い順
- パンくずは実際のリンクにする（トップ → 都道府県 → 市区町村）。
  戻り先も「祭り一覧」ではなくその市区町村の一覧にした
- OGP は `public/ogp.svg` を `scripts/gen-ogp.mjs` で PNG に焼く。
  **X も Facebook も SVG の og:image を表示しない**。
  写真のある祭りはその写真を og:image に使う
- `<link rel=canonical>` と `og:url` を入れた
- 404 ページは行き止まりにせず、都道府県の一覧を出す

### 行政の PDF を読む

行政の祭り一覧は PDF 公開が多く、しかも**権限制限がかかっていて WebFetch でも

### 町会いんふぉ（chokai.info）— 町内会が自分で書いた一次情報

町内会・自治会向けのホームページ作成サービス。**406 団体**が使っている。
新着情報の見出しが決まった形をしていて機械的に構造化できる。

```
納涼盆踊り大会（令和8年8月2日）［五反野西町会］／足立区
```

角括弧が主催団体、スラッシュ以降が市区町村。**出典の格は最上位（official）**。

```bash
node scripts/crawl/chokai-info.mjs
```

robots.txt で **8 つの町内会が明示的にクロールを拒否**しているので、
クローラはその Disallow を読んで該当ディレクトリに一切アクセスしない。

**結果: 322 見出しのうち 290 が既存データと重複**した。つまり町会いんふぉの内容は、
区が公式に出している一覧とほぼ重なる。新規は 33 件。
「一次情報だから新しい情報が取れる」わけではなく、**同じ情報を別ルートで裏取りできる**
という価値のほうが大きかった（区公式データとの突合が取れた）。

- 角括弧は全角［］と半角[] の両方が使われている
- 2026 年の告知がまだ出ていない団体が多い。前年の実績も拾い「2025年の情報です」と明示

### 千葉で見つかった、町内会レベルが取れる媒体

**まいぷれ船橋市**が町内会・自治会単位まで載せていた（習志野台2丁目町会、習志野台みゆき町会、
三咲本通り商店会など）。神奈川でいう「みやまえご近所さん」に相当する立ち位置。
関東の他県でも「まいぷれ」の市版があるかを次に当たる。

**千葉すまいラボ**は神奈川すまいラボと同じ運営で、市町村ごとのページを持つ。
ただし神奈川版と同じく、確定日程が載るのは市を代表する祭りに偏る。

出典の内訳: **主催者の公式発表 1173** / 地域メディア 154 / まとめサイト 83 / 行政 41。

埼玉は 1982 社に対して採用 281 と歩留まりが低い。神社庁の「お祭り」欄が空の神社が
多いため（1982 社中 1500 社超が記載なし）。神奈川・東京は逆にほぼ全社に例祭日がある。

### この工程で潰したバグ

- **東京が 548 社中 75 件しか入らなかった**。インポータの住所分解が東京の特別区
  （前に市がつかない「◯◯区」）に対応しておらず、472 社が丸ごと弾かれていた → 492 件に
- **同じ区の同名神社が消えていた**。重複判定のキーが「市区町村＋神社名＋種別」だったため、
  大田区の稲荷神社のように同名の神社が並ぶと 2 社目以降が全部落ちた。
  神社庁由来のファイルは重複判定の対象から外し、手入力データの保護だけに使うよう変更
- **`gen-areas` が自分の出力を読んでいた**。実行のたびに市町村が減っていた
- **埼玉パーサが「御祭神」の行を拾っていた**（`th.includes('祭')` が誤爆）。
  祭神名を日付として解釈していたぶんをキャッシュから削除し再取得
- **「7月最終金・土・日曜」が 7/25・7/26・7/31 とバラけていた**。曜日ごとに独立して
  「月内最後の◯曜」を取っていたため。最後の金曜から連続 3 日と読むよう修正

**神奈川と埼玉・東京の差、さらにその他4県との差は、祭りの多寡ではなく情報公開の差。**
千葉・茨城・栃木・群馬は神社庁が神社データベースを持っていないため、
1件ずつ手で積むしかない。


町内会レベルの祭りは、まとめサイトを追いかけても集まらない。
**各都県の神社庁が県内全神社の例祭日を公開している**ので、そこを機械的に舐めるのが本線。
まとめサイト・地域メディアは、そこに肉付けする補助線として使う。

## パイプライン

```
crawl（神社庁を巡回）→ gen-areas（市区町村の定義を生成）→ import（祭りデータ化）
  → enrich（一次情報で裏取り）→ validate（門番）→ build
```

```bash
node scripts/crawl/jinjacho.mjs <pref>
```

```bash
npm run collect
```

クロールはディスクキャッシュを持つので、中断してもやり直しにならない。
1リクエストごとに 700ms あけ、User-Agent で素性を名乗り、公開サイトマップからのみ辿る。

### 八百万の神（yaokami.jp）を使わない判断

全国の神社を例祭日つきで横断しているので候補になったが、robots.txt に

```
Content-Signal: search=yes, ai-train=no, use=reference
```

と明示されていた。ai-train は拒否、use は reference まで。ここから一括で抽出して
自分のサイトのデータベースにするのは reference の範囲を超える。加えて yaokami 自体が
神社庁データの集約サイトであって一次情報ではない。**このプロジェクトの「一次情報まで遡る」
という方針とも合わないので、使わない。**

### 千葉・茨城・栃木・群馬をどう埋めるか

神社庁が使えない以上、横浜・川崎でやったのと同じ手作業に戻る。

1. 各神社の公式サイト（香取神宮・鹿島神宮・日光二荒山神社・貫前神社などは自前のサイトを持つ）
2. 市町村の観光協会・行政ページ
3. 地域メディア（号外NET・タウンニュースは関東の広い範囲に版がある）

数は稼げないが、出典の格は上がる。

新しい都県を足す手順:

1. robots.txt とサイトマップを確認する
2. `scripts/crawl/jinjacho.mjs` の `ADAPTERS` に 1 件足す（`base` / `sitemaps` / `accept` / `id` / `parse`）
3. `scripts/lib/romaji.mjs` にその都県の市区町村 slug を足す
4. `scripts/gen-areas.mjs` の `PREF` に足す
5. `npm run collect`

## 日付ルールの解決

神社庁は日付をルールで持っている（`10月第1日曜日`／`9月15日に近い日曜日`／`体育の日`）。
`scripts/lib/jpdate.mjs` がこれを指定年の実日付に落とす。対応済みの書式:

- `N月D日`、`N月D日〜D日`、`N月D日〜N月D日`
- `N月第K◯曜日`（漢数字・全角数字とも）、`N月第K土・日曜日`
- `N月最終◯曜日`
- `N月D日に近い◯曜日`
- 祝日名（海の日・スポーツの日・敬老の日など、ハッピーマンデーを含む）

**ルールから導いた日付は必ず `status: estimated`** にする。神社が今年の日程として
発表したわけではないので、個別ページにもその旨が出る。

## 取り込みの方針

- 参拝者が集まる祭りだけ入れる。月次祭・大祓・祈年祭・新嘗祭・歳旦祭・節分祭のような
  全神社にある内向きの祭祀は、数だけ膨らんで祭り探しの邪魔になるので入れない
- 同じ市区町村・同じ神社・同じ種別の祭りが既にあれば飛ばす（手で入れたデータを守る）
- slug が `romaji.mjs` にない市区町村は取り込まず警告を出す。当て字の slug を勝手に
  作ると、あとから直せなくなる
