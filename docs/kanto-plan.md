# 関東全域への拡大 — 作業計画と進捗

## 屋台・露店の有無をどう集めるか

利用者にとって決定的なのは「屋台が出るか」。集められる入口は限られている。

| 入口 | 使えるもの |
|---|---|
| **花火大会DB**（`hanabi.walkerplus.com/list/<県>/yatai/`） | **屋台の有無を項目として持つ。北関東で唯一まとまって取れる** |
| 夏祭りDB（`summer.walkerplus.com/odekake/list/<県>/sg0999/yatai/`） | 同上。夏祭りのみ |
| 行政一覧の備考欄 | 葛飾区の PDF は「模擬店あり（ラムネ、かき氷…）」まで書いてある |
| 神社の例大祭 | **まず公開されていない**。個別に調べるしかない |

**「屋台」が山車を指す地域がある**（栃木・群馬・埼玉北部の「屋台行事」）。
出典に屋台とあっても意味を確かめること。詳細は `docs/schema.md`。

## 写真

ウィキメディア・コモンズの CC ライセンス画像だけを使う。他サイトの画像は持ってこない。

```bash
node scripts/crawl/commons-photos.mjs --min-scale 市
```

```bash
node scripts/enrich/photos.mjs
```

- ライセンス・著作者・出典ページが揃っていないものは validate で落ちる
- NonCommercial / NoDerivatives は除外
- 祭りの名前から固有語（地名・神社名）を取り出し、画像の題名・説明・カテゴリに
  その語が出るものだけ採用する。これをしないと「かまがやの花火」に
  1875年生まれの人物写真が当たるような誤爆が起きる
- **八幡神社・稲荷神社・諏訪神社のようなありふれた社号は固有語にならない**。
  厚木市の八幡神社に蒲郡市の三谷八幡神社の写真が付いた。これらは
  市区町村名の一致を伴って初めて採用する（`COMMON_SHRINE`）
- **同じ写真が 2 つ以上の祭りに付いていたら、どちらにも付けない**。
  一般的すぎる証拠で、その祭りを指していない
- **神社の祭りは市区町村名か鎮座地の町名の裏づけを必須にする**。社号は全国で
  重複するので、社号の一致だけでは同名の別社をつかむ。大田区の三輪神社に岐阜の
  揖斐祭、新宿の赤城神社に群馬の赤城大沼の写真が付いた。コモンズの題名は
  ローマ字のことも多いので、市区町村の slug も地名の錨に足す
- 「このデータで 1 社しか無い社号なら通す」も試したが**駄目**。
  一意なのはこのデータの中だけで、日本全国では違う（榛名神社・赤城神社）
- 判定に使った材料（説明・カテゴリ）は残しておくこと。題名しか残していなかったので、
  後から見直したとき正しい写真まで落とした。`scripts/crawl/commons-meta.mjs` で取り直す
- **説明に別の土地の名前が出ていたら外す**。札幌の狸まつりに「阿波の狸まつり（徳島）」、
  大阪の天神祭に「伊賀市だんじり会館（三重）」の写真が付いた
- ただし**県境の花火大会は両岸の市が共催する**（市川市民納涼花火大会は江戸川区と、
  関門海峡花火大会は下関市と門司区）。自分の土地の名前が出ていれば他県が出ていてもよい
- 市区町村名で照合するときは**実在の市区町村に限る**。素朴に「◯◯市」を拾うと
  「サギ草市」「錦糸町」を市区町村だと思ってしまう
- 「祭りを写した写真か」も見る。ただし**祭り会場で撮った物の写真は残す**
  （豊田おいでんまつりのピザ屋の車は、その祭りの屋台なので誤りではない）
- **「桜まつり」「駅前夏祭り」「天王祭」「summer festival」のように
  祭りの種類しか言っていない名前**も、神社の祭りと同じく地名の裏づけを要る。
  袋井市の「summer festival」にイタリアの音楽祭、東久留米市の「天王祭」に
  品川の荏原神社の写真が付いた。この規則で京都の祇園祭も巻き添えで落ちるが、
  **間違った写真を残すより取りこぼす方を選ぶ**
- 重複した祭りを先にまとめること。同じ写真が 2 件に付くと両方から外れる
  （「入谷朝顔まつり」と「入谷朝顔まつり(入谷朝顔市)」が半角括弧の違いで
  別物として残っていた）
- Wikimedia の API はレート制限が厳しい。2 秒あけ、429 は Retry-After に従って待つ

判定を厳しくしたら、過去に採った分も同じ物差しで測り直す:

```bash
node scripts/enrich/photos-audit.mjs
```

`--apply` を付けるまで外す候補を並べるだけ。

## 全国展開

関東で神社庁を舐めきったあと、他府県には同種の神社DBがほぼ無い
（愛知はJS描画、大阪・福岡・広島は接続不可、京都・兵庫・静岡・新潟・長野は404）。
代わりに**ウォーカープラスの2つのDBが47都道府県を同じURL規則で持ち、
しかも屋台の有無で絞り込める**。「露店があるものだけ載せる」方針のまま広げられる。

| 入口 | URL | JSON-LD の形 |
|---|---|---|
| 花火 | `hanabi.walkerplus.com/list/<ar>/yatai/` | `WebPage → mainEntity(ItemList) → itemListElement[].item` |
| 夏祭り・盆踊り | `summer.walkerplus.com/odekake/list/<ar>/sg0999/yatai/` | **Event の配列**（1ページ10件） |

`ar` コードは `scripts/lib/prefs.mjs`。HTML の class を追うより構造化データが正確。

**1.2 秒間隔で 47 都道府県を続けて叩いたら 2 県目以降が全部 404 になった。**
本物の 404 ではなく出しすぎの遮断で、時間を空けると 200 が返る。3 秒あける。
なお 2 ページ目以降の 404 は単に最終ページを越えただけなので、待ち直さない。

## ウォーカープラスの詳細ページ — 中身の無いページを埋める

一覧の JSON-LD は**県と市区町村しか持っていない**。以前これを住所だと考えて
全 47 都道府県を再クロールし、**住所を 1 件も得られなかった**。同じ失敗を繰り返さないこと。

住所・時刻・主催があるのは**詳細ページの HTML** のほう。1 枚開いて確かめた結果:

| ページ | ある欄 |
|---|---|
| 花火 `/detail/<id>/map.html` | 会場・会場アクセス・**問い合わせ**・公式サイト・**緯度経度**・開催時間 |
| 花火 `/detail/<id>/data.html` | 打ち上げ数・人出・荒天時。スキーマに無いので取らない |
| 夏祭 `/odekake/detail_e/<id>/map.html` | **住所**・交通アクセス・問い合わせ・緯度経度 |
| 夏祭 `/odekake/detail_e/<id>/data.html` | **開催時間**・公式サイト・屋台の内訳 |

**花火の詳細ページには「住所」の欄が無い。** 一覧にも詳細にも住所は無い、が結論。
代わりに地図の埋め込み URL（`maps/embed/v1/place?q=<lat>,<lng>`）に
打ち上げ場所の緯度経度が入っている。そこから住所を起こす。

```bash
node scripts/crawl/hanabi-detail.mjs            # HTML（3.5秒間隔・約 70 分）
node scripts/crawl/hanabi-detail.mjs --geocode  # 緯度経度 → 住所（国土地理院）
node scripts/enrich/hanabi-detail.mjs           # 書き込み。ここは通信しない
```

- 花火は**開催時間もヘッダに出る**ので map.html 1 枚で足りる。夏祭りだけ 2 枚要る
- 住所は**国土地理院の逆ジオコーダ**（`mreversegeocoder.gsi.go.jp`）で起こす。
  返るのは市区町村コードと町丁目。出典が公的機関なのでまとめサイトより格が上
- **返ってきた市区町村が掲載市と違ったら捨てる**。1045 件中 8 件が該当し、
  市川市民納涼花火大会（対岸が江戸川区）・稲城市（対岸が川崎市多摩区）のような
  県境の大会と、伊達市の大会に山梨県大月市の座標が付いている出典側の誤りだった
- **こちらの市名は「北設楽郡東栄町」と郡付き、国土地理院は「東栄町」**。
  郡を落とした形も突き合わせないと、郡部が全部「別の市」として落ちる
- 「問い合わせ」欄は電話番号＋団体名。厳密には主催ではないが、この規模の花火は
  観光協会・実行委員会・商工会が実施主体を兼ねている。**団体らしい語で終わるものだけ**を
  主催として採り、「◯◯駅観光案内所」のような案内窓口は入れない
- 最寄駅は会場アクセスの**【電車】の側だけ**。【車】の IC 名を最寄駅にしない
- 開催時間は**先頭に錨を打って読む**。「20:30～20:55まつりは…18:00～」の
  後ろ側を拾うと開始時刻が入れ替わる
- `patch()` の `links` は参照で重複を見るので、同じ URL を毎回足してしまう。
  URL で既存を確かめてから渡すこと（enrich は毎回 collect で走る）
- 屋台欄は「あり複数出店予定」「ありキッチンカー出店」のような書き方で、
  **この 2 つの DB に山車の意味の「屋台」は 1 件も無かった**

結果（1045 件中）: 住所 924 / 最寄駅 973 / 公式サイト 1007 / 主催 806 / 開催時間 638 / 緯度経度 1045。

## 重複

全国のまとめサイトを入れたら、関東で一次情報から入れていた祭りと重なった
（手賀沼花火大会が 2 件など）。

```bash
node scripts/dedupe.mjs        # --apply で実行
```

**同じ市に同じ名前の祭りが複数あるのは普通のこと**なので、名前一致だけで
まとめてはいけない。平塚市には八坂神社例祭が 3 つあり、東八幡・飯島・纒の
別々の神社の祭り。そこで**まとめサイト由来を含む組だけ**を対象にする。
実際、対象 44 組に例祭型は 1 つも無く、非対象 93 組は全て住所の違う別の神社だった。

残す方は出典の質で決め（公式 > 行政 > メディア > まとめ）、消す方が持っていた
屋台の有無・写真・日付・出典リンクは残す方に移す。

## 埼玉神社庁の「お祭り」欄は書き方が 2 通りある

```
(a) ５月３日 例祭 10月15日 神嘗祭      … 日付 → 祭名
(b) 夏祭（７月２０日）、例大祭（１１月３日） … 祭名（日付）
```

(b) を (a) の規則で読むと、**日付に次の祭名が付き、名前も括弧ごと壊れる**。
「）、例大祭（」という名前の祭りが 21 件出来ていた。しかも最初の祭りの名前が
消えるので、日付と祭名の対応が 1 つずつずれる（八幡大神社の７月２０日は
例大祭ではなく天王祭だった）。(b) を先に試すよう直し、52 社を取り直した。

## 出典が中止・去年の日程のまま、ということがある

まとめサイトの一覧には、**名前に「【2026年中止】」と書かれたまま**の項目が
13 件あった（海の日名古屋みなと祭花火大会など）。名前で弾く。

前年の日程のまま更新されていない項目も 102 件ある。こちらは消さずに、
`occurrences[].note` に「出典は2025年の日程のまま。2026年の開催は発表されていない」
と書いて載せる。**日付が今年のものだと誤解させないこと**が要点。

## まいぷれ（地域情報サイト）

`robots.txt` が **Crawl-delay: 90** を宣言している。必ず 90 秒あけること。

```bash
node scripts/crawl/mypl.mjs suginami   # 90 秒間隔で取得
node scripts/import/mypl.mjs suginami
```

記事本文が「月 / イベント名 / 会場 / 開催日 / 時間」の表なので、表の行として読む。
杉並区で 13 件（うち屋台の明記 3 件）。ただし**記事の URL は地域版ごとに違い**、
`summer-fes_<area>` が通ったのは杉並だけ。越谷・所沢は 404。一括では取れない。

## 号外NET — 町内会レベルが全国で取れる唯一の入口

**地域版が 284 ある**（北関東や地方都市も含む）。しかも WordPress の REST API が
開いていて検索語つきで記事を引ける。

```bash
node scripts/crawl/goguynet.mjs      # 285地域 × 5語、1.5秒間隔
node scripts/import/goguynet.mjs
```

記事の本文が決まった形をしている:

```
～納涼盆踊り～ 日時 2026年8月1日（土）16時～21時 場所 都立汐入公園噴水広場周辺
```

- 市区町村は**題名の【】**から取る（地域版が複数市をまとめていることがあるため）
- 見出しが「青森県・岩手県・宮城県」のように複数県のことがある。市名で引き、
  候補が複数なら見出しの県で絞る
- 政令市の区も題名に出る（「【中原区】…」）ので区としても引けるようにする
- **「場所」は地の文にも出る**。「場所には多数の売店も出店予定となっており…」を
  会場にしてしまった。助詞・文末表現で始まるものは捨て、「◯◯で開催」から拾うときは
  公園・神社・小学校など**場所らしい語で終わるもの**に限る
  （「全体が一体感に包まれる」を会場にしていた）
- 「雨天の場合は8月2日に順延」の予備日を開催日にしない
- **「日時」という欄があるのは一部だけ**。多くは地の文で
  「2026年7月31日（金）から8月2日（日）まで開催されます」と書く。
  欄が無いという理由で捨てたら 377 件落ちていた。地の文から拾うときは
  本文の頭 400 字に限る（後半には「昨年は…」の日付が出る）
- 名前は「東山温泉盆踊り2026」のように**鉤括弧**で括られることが多い
- 題名の【】には「2026年最新」のような市区町村でないものも入る。
  そのまま登録すると「号外NET（2026年最新）」というエリアができる
- **同じ祭りを複数回記事にする**（告知と当日レポート）。dedupe の対象に含める
- 「夏祭り」だけの総称や「午後9時 ・花火大会 午後7時30分」のような
  抜き出し損ねは、どの祭りか分からないので捨てる
- 店舗の集客企画（「夏祭りファミリーDay」等）は地域の祭りではないので除く
- **名前は題名の鉤括弧を先に見る**。地の文から切り出すと
  「多くの人で賑わう「八坂神社祭」のように途中で切れる（正しくは八坂神社祭礼）
- 鉤括弧の中が「夏祭り」だけのことがある。直前の主催者・会場を前に付ける
  （「紅葉八幡宮で「夏祭り」開催へ」→ 紅葉八幡宮 夏祭り）
- 検索語は 5 語では足りず、12 語に増やした（秋祭り・祭礼・夜店・盆おどりなど）。
  取得済みの語は飛ばして足りない分だけ引く（全部取り直すと 85 分かかる）

## レアリア（rarea.events）

神奈川・東京中心の地域イベント媒体。号外NET と同じく WordPress の REST API が開いている。
**自治会・町内会が主催する祭り**を、縁日ブースやキッチンカーの記述つきで書く。

```bash
node scripts/crawl/rarea.mjs
node scripts/import/rarea.mjs
```

題名に日付と市区町村が素で入る（【】ではない）:

```
2026年8月15日　厚木市　森の里若宮公園で夏祭り
…8月16日は「富士見公園夏まつり」＠川崎市川崎区
```

市区町村は**既に定義してある名前だけを拾う**。素朴に「◯◯市」を拾うと
祭りの名前の一部を市だと思ってしまう。政令市の区を先に見る
（「川崎市川崎区」が「川崎市」より先に当たるように長い名前から順に）。

3月以降の記事に絞ると 72 件。号外NET より小さいが粒度は同じ。

## 東京フェスタ（tokyofesta.com）

東京の祭り専門の媒体。WordPress の REST API が開いている。
書き方が号外NET・レアリアより整っていて、本文が箇条書き:

```
日時：2026年8月28日(金)〜29日(土) 18:30～20:30
会場：京橋中央ひろば（ガレリア）
主催：京橋一の部連合町会
```

**主催が町会名で書かれている**ので、町内会の祭りかどうかを規模の判定に使える。

```bash
node scripts/crawl/tokyofesta.mjs
node scripts/import/tokyofesta.mjs
```

- 「日時：」の**全角コロン**に対応が要る（`pickDates`）
- 主催の抽出で「主催：Park」「主催：BUBBLE」と本文の英語部分を拾っていた。
  団体名なら日本語が入るので、それを条件にする
- **記事に区名が出ず、街の名前だけのことが多い**（「渋谷キャスト」「巣鴨駅南口」
  「自由が丘駅前」）。よく出る街を区に対応づける表を持つ。
  これで市区町村不明が 50 → 26 件に減り、取り込みが 39 → 57 件になった
- 「絶品グルメ☆ビール＆日本酒祭り＠神田明神納涼祭り」のように
  記号でつないだ前半が煽り文句。`＠` の後ろが本題
- **東京フェスタは 23 区だけの媒体ではない**。武蔵野・立川・府中・稲城も出る。
  エリア定義に無い市は `citySlug` が引けるものだけ足す
- **都外の祭りも少し載る**（横浜・川越・所沢・柏の葉・江の島）。
  全国のエリア定義で当てにいくと同名の市で誤判定した:
  「しながわスネークタウン（蛇窪神社）」→ 神奈川県大井町、
  「すもも祭（府中市・大國魂神社）」→ 広島県府中市、
  「新潟フェス in 東急歌舞伎町タワー」→ 新潟県長岡市。
  **この媒体は東京都に限る**。都外は他の媒体で拾う
- **題名がそのまま祭りの名前**。本文は時刻表なので、そちらから拾うと
  「21:00 （盆踊り大会17:00」のような切れ端になる。題名を先に使う。
  なお**号外NETの題名は文章**（「【荒川区】8月22日（土）、…が開催されます！」）
  なので、この直し方は東京フェスタにしか効かない
- 「盆踊りエリア」「おまつり広場」は会場の区分であって祭りの名前ではない。
  **会場名を祭り名にすると写真も引きずられる**（八戸市の「おまつり広場」に
  「仙台七夕まつり おまつり広場」の写真が付いた）

## 会場名を「自治体の施設一覧」に突き合わせて住所を起こす

行政の祭り一覧は**会場名しか持っていない**ことが多い（「若松台小学校」「城山公園」）。
住所が無いと地図が引けない。1 件ずつ検索して裏を取るより、
**その自治体が出している施設一覧と機械的に突き合わせる方が桁違いに速い**。

```bash
node scripts/crawl/opendata-facilities.mjs      # 施設一覧を取得（キャッシュ）
node scripts/enrich/venue-address-opendata.mjs  # 突き合わせて住所を入れる
```

取り違えないための決まり（**外さないこと**）:

1. **市区町村（政令市は区）までキーに含める。** 堺市南区の祭りは堺市南区の施設としか照合しない
2. **会場名が完全に一致したときだけ採る。** 部分一致は使わない
   （「美木多上公園」と「美木多公園」は別の公園でありうる）
3. **候補が指す住所が 2 通り以上あるものは捨てる。**
   足立区の「氷川神社」2 社、「東綾瀬公園」3 か所はこれで正しく落ちた。
   逆に**同じ住所を指す重複は採ってよい**（1 つの公園を複数の町会が使う）

見つかった入口（種類ごと）:

| 自治体 | 何が取れるか | 形式 |
|---|---|---|
| **東京都（全域）** | **避難所・避難場所**＝小中学校・公園・広場。**23区市町村を横断** | CSV（都総務局 防災マップ） |
| 堺市 | 小学校（住所・**緯度経度**）・公園 | CSV（BODIK） |
| 名古屋市 | 都市公園（区ごと）・区の小中学校一覧 | CSV（BODIK）／HTML |
| **大阪市** | **学校・公園・児童遊園・広場・会館・地域集会所**（住所＋緯度経度） | CSV（マップナビおおさか） |
| 神戸市 | 避難所（＝小中学校の住所）・地域福祉センター | CSV（wagmap） |
| 足立区 | 都市公園／**盆踊り一覧そのものに「住所」列がある** | CSV／HTML |
| 江戸川区 | 貸出可能施設（会館） | CSV |
| 県神社庁 | 神社の鎮座地 | 既存のクロール結果を流用 |

**「避難所一覧」は学校の住所の代わりになる。** 学校一覧をオープンデータにしていない
自治体でも、小中学校はほぼ全部が指定避難所なので住所が公開されている（神戸市で確認）。
**都道府県が全市区町村ぶんをまとめて出していることがある**ので、区ごとに探す前に
都道府県のカタログを見ること（東京都はこれ 1 本で 23 区に効く）。

**大阪市と神戸市と中野区は同じ地図基盤（wagmap）**で、CSV の列の形まで同じ
（`施設名称 / 所在地 / 経度 / 緯度`）。1 つ読めれば他も同じ処理で読める。

- **マップナビおおさかは Node の fetch が TLS を拒む**（`ERR_SSL_DH_KEY_TOO_SMALL`）。
  curl では取れるので、落ちたら手で置く
- **CSV でなくてよい。** 足立区は「あだちの盆踊り」一覧の HTML の表に住所の列があり、
  ここだけで **85 件**埋まった。取り込みのときに会場名しか拾っていなかった見落とし
- 逆に**江戸川区は住所を持っていない**。地区別の一覧はどれも
  「行事／日程／会場」までで、所在地は区の地図サービス側にしかない

### この方法が効かないもの

- **会場名が場所を指していないもの。** 大田区・北区・葛飾区・荒川区・町会いんふぉ由来は
  会場が「◯◯町会 地域内」「会場は主催者に要確認」で、出典が場所を書いていない
- **神社・寺**。施設一覧に載らないので、社号だけでは全国の同名社と区別できない

### 国土地理院の地名検索は使わない

住所から緯度経度を引くのには使えるが、**施設名では当たらない**。
前方一致で近い住所を返すので、「末若氷川神社」で**兵庫県三田市末**、
「此花公園」で**春日出北一丁目**（無関係な町丁目）が返った。
もっともらしい別の場所が入るのがいちばん危ないので、この用途では使わない。

## 薄いデータを「検索で公式ページを探して」埋める

名前・日付・会場名しか無い祭りは、**元の出典を掘り直すより、その祭りの公式・行政ページを
新しく探す方が早い**。`scripts/enrich/primary-4.mjs` に 80 件ぶん入れた。

### 効いた検索の当て方（当たった順）

| 当て方 | 当たるもの | 備考 |
|---|---|---|
| `<祭りの名前> <市区町村名> 主催 会場 時間` | 住所・時刻・主催が一度に出る | **いちばん歩留まりが高い**。4 語を並べるだけ |
| `<祭りの名前> <市区町村名> 2026` | 今年の日程・時刻 | 年を入れると前年のページに引っ張られにくい |
| `<神社名> <市区町村名> 住所 公式` | 神社の住所・例祭日の決まり | 神社は自前サイトを持っていることが多い |
| `<祭りの名前> <会場名> 主催` | 会場が実は別だった場合 | 「淵野辺駅周辺」→ 鹿沼公園、「赤城山」→ 赤城大沼湖畔 |

- **市区町村名を必ず入れる**。入れないと同名の別の祭りが上位に来る
  （「祇園祭」「天王祭」「よさこい」は全国にある）
- 出てきたページが**その市区町村のものか**を、ページ内の住所か市区町村名で確かめる。
  確かめられないものは埋めない
- **`.lg.jp` と観光協会が最も確実**。市区町村は「令和8年度◯◯まつり」の形で
  毎年ページを作り直すので、年を入れて検索すると今年のページに当たる
- 主催者が**プレスリリース（PR TIMES）で出していることがある**（笠間納涼盆踊り花火大会）。
  これは主催者の公式発表なので `official` に上げてよい
- **町の商工会・商店会が主催**の祭りが多い（氏家商工まつり・鬼石夏祭り・門司みなと祭）。
  市のページに無ければ商工会を探す

### 埋めるときの線引き

- **時刻は同じ年の発表から取る**。前年しか無いものは
  `occurrences[].note` に「時刻は前回の発表による」と書いてから入れる
- 一日の中で時間帯が分かれるもの（宵宮と本宮、神事と本祭）は
  全体の時間帯を `start_time`/`end_time` に入れ、内訳は `note` に書く
- **出典の文章は持ち込まない**。拾うのは住所・時刻・主催者名・URL だけ

### 埋まらなかったもの（理由）

| 理由 | 例 |
|---|---|
| 公式ページがそもそも無い | 四万水涼祭、二十三夜祭、足尾町納涼祭、塙の天祭、宮壹祭 |
| 今年の情報が未発表 | 宇都宮城址まつり（2025年のページまでしか無い） |
| 会場名しか手がかりが無い町内会規模 | しらゆり公園 納涼盆踊り大会、本牧0縁日、相之川 盆おどり |
| 使わないと決めた媒体にしか出ていない | みどりサマーフェスタ（住所はいこーよにしか無かった） |

## 政令市の区の一覧は「祭りの一覧」とは限らない

門司区のページは**区内の年間行事カレンダー**で、北九州マラソン・清掃活動・
イルミネーション・帆船の一般公開まで同じ表に並んでいた。表単位の判定
（`NOT_FESTIVAL_TABLE`）では落とせないので、**行単位の除外**を足した
（`NOT_FESTIVAL_ROW`）。落としたものは実行時に一覧で出す。

- **表のリンク文言が名前に入る**。「北九州マラソン2026（外部リンク）」が
  そのまま id になっていた。id は名前から作るので、名前を洗ってから id を作る
- **時間の列を読んでいなかった**。`roleOf` は `time` を返すのに使っていない。
  名東区・住吉区・堺市南区・美浜区は時間の列を持っている（59 件に時刻が入った）
- 「午後5時~9時」は後ろの午前・午後が省かれる。素直に読むと 17:00→09:00 になる
- 「夜店17時30分～／花火20時頃～」の 20 時は**終了時刻ではない**。
  `〜` で直結した 2 つだけを開始・終了の組とみなす
- 西淀川区は 2 つめの表が `<caption>神社のおまつり</caption>` で、
  **名称欄が神社名・場所欄が鎮座地の住所**。地域の盆踊りの表と同じ規則で読むと
  「五社神社」という名前で会場が「中島1-2-8」になる
- 会場欄の括弧の中が住所とは限らない。「（イベント会場：杉守神社）」
  「（学園大通り口）」を住所にしていた。**数字を含むものだけ**住所とみなす
- 主催の欄には問い合わせ先の電話番号が続く。主催者名だけにする

## 政令市の区が町会レベルの一覧を作っている

東京の足立区・江戸川区・葛飾区と同じ型が、**大阪市・名古屋市**にもあった。
名古屋は区ではなく**学区**単位。

```bash
node scripts/crawl/city-ward.mjs
node scripts/import/city-ward.mjs
```

**列の並びが区ごとに違う**:

```
西淀川区: 地域 / 名称 / 開催日 / 場所
此花区:   行事 / 日時 / 場所
名東区:   行事名 / 日にち / 時間 / 場所
```

列の数で決め打ちすると名東区で「日にち」を場所だと思ってしまう。
**見出し行から列の意味を読む**こと（`roleOf`）。

- ページの URL は区ごとにばらばらで規則から導けない。`PAGES` に足していく
- 「8月14日(金曜日)、8月15日(土曜日)」のように複数日のことがあるので全部拾う
- **「予備日7月5日」は雨天時の日程**なので開催日ではない
- 名前に付く「※」は注記の印
- 「酉島夜店と花火大会」のように名前や日時欄に夜店とあれば屋台は確定できる

現在: 西淀川区 22 / 此花区 8 / 名東区 15 ＝ **45 件**。

調べたが表になっていなかったもの: 大阪市旭区（PDF だが画像）、
大阪市城東区・東住吉区（地域名の一覧のみで日程が無い）、
名古屋市緑区（表が無い）、名古屋市昭和区（表はあるが防災訓練の種目表）。

**札幌市には無い**。「◯◯区どさんこプレス」型の媒体は東区だけで、
他区の subdomain（chuoku / kitaku / shiroishi / toyohira / teine / nishiku /
minamiku / atsubetsu / kiyota）はいずれも存在しない。

## 記事から祭りを取り出す処理は共通化した

`scripts/import/_article.mjs`。号外NET とレアリアで同じ癖に当たるため。
**ここの条件はすべて実データで誤りを見つけて足したもの**。消すときは再発しないか確かめる。

- **送り仮名の無い「祭」**で終わる名前がある（万灯みたま祭・吉原祇園祭・妙見大祭）。
  `IS_FESTIVAL` に入れないと神社の祭りがまとめて落ちる
- 「2026年胡録神社例大祭」の年は名前ではない。残すと「日付が混ざっている」として
  落としてしまい、荒川区の主要な祭りが消える
- 会場に「９月26日・27日に美しが丘公園」と日付が前置されることがある
- 題名から名前を切り出す最後の手段は文を拾いやすい。
  「龍城ケ丘自治会が初の夏まつり」「川崎港で夏の納涼祭」は名前ではない
- キッチンカー・縁日ブースも屋台のうち
- **祭りの名前は題名の終わりの方に置かれる**。候補が複数あれば後ろを採る
  （「子供みこしや提灯山笠が…♪ 7月14日 二日市八幡宮夏季大祭」）
- 「2026まちなか夏祭り」のように年だけ前置される。年を落としてから判定しないと
  「日付が混ざっている」として捨ててしまう
- 「夏はホークス！天神夏まつり2026」の煽り文句は落とす（感嘆符の後ろが本題）
- 「今年は覚王山夏祭」の頭の言葉も名前ではない
- 呼びかけ文をそのまま名前にしない（「今年は蒲郡花火大会へ行こう！」
  「レシートを集めて夏まつり」「祭りが始まるぞー！」）
- 総称の前に付ける主催者・会場は、鉤括弧から離れていることがある
  （「我孫子市民プラザで、7月25日(土)に「夏まつり」が開催」）
- **九州の媒体は「令和8年7月25日」と和暦で書く**。読めないとその地域が
  まるごと落ちる。全角数字も混在する（「6月６日（土）」）
- 「7月24日・25日」「7月27日と28日」のように 2 日目以降の月が省かれる。
  月を補ってから読む
- 年が書かれていないときは**記事の掲載年**を既定にする。本文に出てくる年を
  拾うと回顧の文（「2025年は…」）の年を付けてしまい、去年の日付が混ざる
- 名前に時刻が混ざることがある（「祭典 17:00過ぎ」「盆踊り：18:00」）。
  本文の時刻表から切り出したもの
- 「7月30日は美奈宜神社で夏越祭」のように**日付が前に付く**題名がある。
  日付を落としてから名前を切り出す
- 「◯◯で△△祭」の△△だけを採る案は**駄目**。△△が総称のときに
  「川崎港で夏の納涼祭」→「夏の納涼祭」となって悪化する

## 記事を掘り直して住所・時刻・主催・公式リンクを埋める

```bash
node scripts/crawl/article-html.mjs            # 取り込み済み記事の HTML を取り直す
node scripts/enrich/article-refill.mjs         # --apply で実行
```

取り込み（`import/goguynet.mjs` ほか）は名前・日付・会場名までしか拾っていない。
記事にはもっと書いてあるので後追いで埋める。**記事の文章は持ち込まない**。
拾うのは住所・時刻・主催者名・リンク先 URL という事実の項目だけ。

### なぜ HTML を取り直すのか

`crawl/goguynet.mjs` などは `strip()` でタグを落としてから保存している。そのため
**Google マップ埋め込みの iframe と `<a href>` が生データに残っていない**。
住所と緯度経度はこの iframe にしか無いので、`include=` で id 指定して引き直す
（1 サイト 1 リクエスト。新しい記事は探さないので search は使わない）。

robots.txt は 3 媒体とも `/wp-admin/` のみ Disallow、Content-Signal の指定も無い。
`search=zzzqqqxxx` が 3 媒体とも 0 件を返すことを確認済み（search を無視する媒体ではない）。

### 記事に何が書かれているか（891 記事を読んで分かったこと）

| 項目 | 記事にある割合 | どこにあるか |
|---|---:|---|
| 開催時刻 | 約 45% | **日付の直後**。「日時 2026年8月22日（土）18時～20時30分」 |
| 緯度経度 | 約 65% | Google マップ埋め込み `maps/embed?pb=…!2d<経度>!3d<緯度>` |
| 住所 | 約 9% | 主に `maps/embed/v1/place?q=<会場名>,+<住所>` の形の埋め込み |
| 主催 | 約 11% | 「主催：◯◯」「主催は◯◯です」「◯◯主催による」 |
| 公式リンク | 約 15% | アンカーが「公式サイト」「◯◯神社公式HP」 |

**住所は本文にほとんど書かれていない**（「住所」欄があるのは 1%）。
一方で地図は大半の記事に貼ってある。地図の `pb` 形式は地名と緯度経度しか持たない
ため、住所より緯度経度のほうが多く取れる。

### 誤りを避けるために入れた条件

- **まとめ記事が多い**（「8月1日・2日の◯◯エリアイベントまとめ」）。1 記事に複数の
  祭りと時刻が並ぶので、日付の近くの時刻を素朴に採ると別の祭りの時刻が入る。
  日付ごとに拾った候補が**食い違ったら入れない**。主催と公式リンクは
  まとめ記事からは採らない（地図が 3 つ以上あるものもまとめ記事とみなす）
- 地図が複数あるときは**会場名と一致する地図だけ**を使う。緯度経度は
  会場名が一致したときにしか入れない
- 時刻は「午前10時から午後4時まで」の書き方が 3 割弱ある。直さないと
  「午後4時～9時」を 4:00～9:00 と取り違える
- 住所は**必ず掲載市区町村と突き合わせる**。さらに地の文を弾くため
  使える文字を漢字・カタカナ・数字・「の」「丁目」「番地」「号」に限り、
  末尾が番地らしいことを求める。これが無いと
  「印西市大森にある六軒厳島神社の…」「茅ヶ崎市は6月5日」「津市合併20周年」
  「鈴鹿市駅から徒歩約5分」を住所にしていた
- 「新宿区2-9-2」のように**町名が抜けた住所**は出典の書き落とし。別の場所を
  指すので捨てる
- 長音符「ー」を半角ハイフンに正規化してはいけない。「センター」が「センタ-」になる

### 進捗（2026-08-05 時点）

記事媒体由来の 910 件（`-goguynet-` 654→841 / `-rarea-` / `-tokyofesta-`）のうち、
住所・時刻・主催・リンクがすべて空だったものは **794 件 → 340 件**。

| 項目 | 前 | 後 | 増分 |
|---|---:|---:|---:|
| `venue.address` | 4 | 124 | +120 |
| `venue.lat` / `lng` | 0 | 140 | +140 |
| `occurrences[].start_time` / `end_time` | 0 | 400 | +400 |
| `organizer` | 45 | 83 | +38 |
| `links` | 80 | 195 | +131 |

**緯度経度はこれがデータ全体で最初の 140 件**（それまで 4243 件すべて null）。
地図の埋め込みからしか取れないので、他の出典では埋まらない。

残り 340 件が埋まらない理由は、記事が**祭りの名前と日付だけを短く伝えるもの**
だから。時刻も会場の住所も書かれておらず、地図も貼られていない。
再クロールしても増えない。一次情報（主催者・神社の公式）に当たるしかない。

### 次に効きそうなこと

- 緯度経度が 140 件取れたので、**逆ジオコーディングで住所を起こせる**
  （国土地理院の LonLatToAddress など）。住所が 9% しか書かれていないという
  記事側の限界を、こちらで超えられる唯一の道
- 記事に「アクセス」欄（最寄駅・徒歩◯分）が 6%、「駐車場」が 22% ある。
  `station` は既に schema にあるので拾える

  `date_note` に落とせる
- 同じ記事 id が別の市の祭りとして二重に取り込まれているものがある
  （`tokyo-006-goguynet-16707` と `tokyo-008-goguynet-16707` など）。

## 記事から屋台の有無を埋める

```bash
node scripts/enrich/stalls-from-articles.mjs   # --apply で実行
```

号外NET・レアリアの記事 1500 件のうち、祭りとして取り込めたのは一部。
残りにも**既にある祭りの屋台の記述**が入っている。神社の例祭は神社庁からは
屋台の有無が分からないので、ここで埋められると大きい。

誤って yes にしないための条件:

- 記事の市区町村が一致すること
- **題名に名前が出ていること**。本文のどこかに出ているだけだと、別の祭りの記事で
  言及されただけのものを拾う（石濱神社納涼大会の記事で諏方神社を yes にしていた）
- 社号だけの一致は使わない（「八幡神社」では同名の別社をつかむ）
- **同じ神社に祭りが複数あるときは上げない**。白旗神社（藤沢市）には例祭・
  どんど祭・秋祭があり、7 月の白旗まつりの記事で 3 つとも yes にしていた。
  同じ神社でも祭りが違えば屋台の有無は違う（馬絹神社の 7 月は神事のみ、
  10 月は露店が多い）

**同じ神社に複数あっても、日付が合えばどの祭りか決まる**。記事の 845 件中
800 件に日付があるので、月日の一致を条件に足した。これで白旗神社（藤沢市）の
例祭だけを正しく上げられる。

ありふれた社号でも**鎮座地の町名**を伴えば一意になる（「厚木市及川」の八幡神社）。
条件には入れたが、題名に町名と社号が両方出る記事は無く、増えなかった。

## サイトの構成（2026-08-05 に作り直した）

**トップに全件を並べていたら 2.9MB になっていた。** 携帯で開ける大きさではない。
地域でページを割り、それぞれが扱う件数を絞った。

| URL | 中身 | 大きさ |
|---|---|---:|
| `/` | 都道府県の入口＋これから開催の 120 件 | 101KB |
| `/a/<県>/` | 市区町村の入口＋これから開催の 150 件 | 105〜114KB |
| `/a/<県>/<市>/` | その市区町村の全件 | 最大 174KB |
| `/f/<id>` | 祭りの詳細 | — |

- 一覧は `src/components/FestivalList.astro` に切り出して 3 か所で使い回す

- 「◯◯市 盆踊り 2026」で探す人が直接たどり着ける入口にもなる
- ページが 4700 を超えたので `@astrojs/sitemap` と `robots.txt` を入れた。
  詳細ページより**エリアのページを優先**して巡回してもらう

### 絞り込み

一覧の部品は次で絞れる。すべてブラウザ側で、ページ遷移なし。

| 手段 | 備考 |
|---|---|
| 期間（これから／今週末／すべて） | 既定は「これから」。今週末は金土日 |
| 種別 | そのページに実在する種別だけ出す |
| 月 | 開催のある月だけ出す。**月を選んだら期間を「すべて」に切り替える**（過ぎた月で 0 件になるため） |
| 屋台あり | 確認できたものだけ。未確認は出さない |
| 名前・会場・町会名で検索 | 20 件を超えるページだけ。空白区切りの AND |

検索の対象は名前・会場・主催・神社・市区町村。町内会の祭りは
「◯◯町会」「◯◯公園」で探されるので、その両方に当たるようにしてある。

都道府県の並びは**地理順（北から南）**。件数順だと東京・神奈川が先頭に来て、
自分の県を目で追えない。`scripts/lib/prefs.mjs` の順をそのまま使う。

  写真のある祭りはその写真を og:image に使う
- `<link rel=canonical>` と `og:url` を入れた
- 404 ページは行き止まりにせず、都道府県の一覧を出す

## 全国ローカルニュースサイト名鑑（news.gotouti.jp）— いちばん大きい鉱脈だった

**1,736 の地域メディアが 1 記事 1 媒体で登録されている索引。** 号外NET・つーしんを
1 件ずつ手で足していた作業を、ここから機械的に広げられる。

```bash
node scripts/crawl/gotouti-index.mjs    # 索引（1 サイト・約 90 リクエスト）
node scripts/crawl/gotouti-media.mjs    # 各媒体の記事（ホスト単位で並列）
node scripts/import/gotouti.mjs
```

記事本文が `<dl>` の定義リストで、**URL・行政区域・プラットフォームが構造化されている**:

```
<dt>URL</dt><dd><a href="https://kashiwa-tsushin.com/">…</a></dd>
<dt>行政区域</dt><dd>千葉県柏市</dd>
<dt>プラットフォーム</dt><dd>WordPress</dd>
```

ここが効く理由は 2 つ。

1. **「プラットフォーム: WordPress」で絞れば REST API が開いている見込みの媒体だけ選べる**
   （1,736 中 1,207 が WordPress）
2. **行政区域が県名つきの市区町村名**なので、市区町村を記事から推測しなくてよい。
   号外NET で苦労した「題名の【】を読む」処理が要らない

### 索引そのものの取り方

- `per_page=100` だと**相手が PHP のエラー HTML を 200 で返す**（本文が重い）。
  20 件ずつ。失敗したら窓を半分に割って取り直す
- **`x-wp-totalpages` はエラー時に返ってこない**。`Number(null ?? 1)` が 1 になって
  ページ送りが 1 ページで終わっていた。ページ番号ではなく offset で数えること

### 媒体を叩く前に必ず確かめること

| 条件 | 落ちた数 |
|---|---:|
| robots.txt に Content-Signal `ai-train=no` | 17 |
| robots.txt が `/wp-json/` を Disallow | 10 |
| `search=zzzqqqxxx` が 0 件を返さない（search を無視する媒体） | 1 |

**並列はホスト単位にする。** 1 ホストの中は直列で 2 秒以上あける。相手が違えば
同時に叩いても相手の負荷にはならないので、10 並列で 1,048 媒体を 1 時間強で回せた。

### 当たらなかったもの（次に無駄足を踏まないための記録）

| 理由 | 媒体数 | 中身 |
|---|---:|---|
| 媒体が消えている（DNS が引けない） | 132 | **名鑑には閉鎖済みの媒体が 1 割強混ざっている** |
| REST 不可 | 115 | WordPress を名乗っているが API が閉じている・移転済み |
| robots.txt が取れない（TLS・タイムアウト） | 66 | 証明書のホスト名不一致が多い |
| 守備範囲が 13 市以上 | 2 | 市の判定を誤りやすいので除外 |

### 「行政区域が県までしか無い」媒体を救う — 名鑑そのものを地名辞書にする

**県までしか書いていない媒体が 59 あり、そこに 562 記事あった。**
しかも群馬・栃木・茨城・山形・鳥取・宮崎・福井・長野という、
このサイトがいちばん薄い県ばかり。「市が決められない」で捨てるのは惜しい。

**名鑑 1,736 媒体分の「行政区域」欄を集めると 1,397 件の市区町村名の辞書になる。**
全国の市区町村表を別に持ち込むより、出典と同じ表記で揃うぶん確実。
これで**題名に市名が出ている記事だけ**を拾えるようになり、
栃木 11 件・鳥取 10 件・長野 13 件・群馬 4 件が取れた。

- 市を決めるのは**題名だけ**を見る。本文には近隣の市の名前も出る
- 2 文字の地名（原村など）は誤爆するので使わない
- 「つくば市」と「つくばみらい市」が両方当たる。長い方だけ残す
- **4 県以上をまたぐ媒体では使わない**

この辞書は「別の市の記事を弾く」判定にも効く。以前は
**既に登録済みの市（`byCity`）としか照合していなかった**ので、
まだ載せたことのない市の名前が素通りしていた（登米市の媒体に
栗原市・一関市の祭りが入っていた）。

**`.{2,6}[市区町村]` という正規表現で市名を切り出してはいけない。**
貪欲に伸びて「西都市中心市街地」から「西都市中心市」という実在しない名前を作る。
市区町村で終わる位置ごとに、長い方から辞書に当てること（`citiesIn`）。
これを直すまで、宮崎県の媒体の「西都夏まつり（西都市中心市街地）」が
宮崎市の祭りとして入っていた。

- **`www` を落としてはいけない。** `hostOf` で `www.` を剥いだホストに接続していて、
  `www` でしか引けない媒体が全部「消えている」に落ちていた
- **`/wp-json/` が塞がれていても `?rest_route=/wp/v2/posts` は開いている媒体がある**
  （セキュリティプラグインが前者だけを弾く）。両方試すと 27 媒体が復活した。
  ただし **200 で HTML を返す媒体が多い**ので Content-Type も見ること

### 取り込みで足した条件

- **地域メディアは隣の市の祭りも記事にする。** 船橋つうしんの「市川市民納涼花火大会」を
  船橋市の祭りとして入れていた。題名に実在する別の市区町村名が出ていて、
  自分の市の名前が出ていなければ捨てる
- **まとめ記事は丸ごと捨てる。** ばらばらの日付が 4 つ以上出る記事は
  「8月1日〜7日イベントまとめ」型で、日付・時刻・会場が混ざる
- **日付が 14 日以上離れたものは読み違い**（「7月18日…8月31日」を 1 つの祭りにしていた）
- 名前の切れ端を落とす（`brokenName`）。「/23（土）24（日）浦安市堀江・久助稲荷神社にて
  久助稲荷大祭」「までです。 住吉神社例大祭期間中（7/14」「”のぼり”がお祭りを

- 商業施設の集客企画を落とす（`COMMERCIAL`）。イオンモール・ららぽーと・
  Suicaのペンギン・周年記念・誕生祭・リゾート
- **`lookup()` が「同名の候補が複数」で null を返すと create() が呼ばれ、
  create() が byCity に足すので次も null になり、同じ市に slug が無限に増える。**

  指す場所が同じなら 1 つにまとめ、既に登録済みの名前では create しない

### 江東区の PDF を読む（列の境界の決め方）

`pdf-text.mjs` は y 座標だけで行に均すので、**日付が 2 行に折り返す行が壊れる**。
x 座標も使って見出しから列を割る必要がある（`scripts/crawl/koto-pdf.mjs`）。

- **見出しの左端の中点でよい。ただし NO 欄だけは幅が狭く**、中点を取ると
  名称の本文（左寄せ）が NO 側に落ちて**名称欄が丸ごと空になる**。
  NO 欄は中身が数字だけなので、数字の右端から境界を引く
- 見出しの中央（左端＋幅/2）で割るのも駄目。今度は 1 つ右にずれた
- 行の切れ目を NO の y の中点にすると、**3 行に折り返したセルの最後の行が
  次の行に食われる**（「納涼こども花火まつ」で切れて「り」が落ちた）。
  行内の行送り（中央値）より広い隙間のうち、中点にいちばん近いものを境界にする
- **出典に誤記がある**（「19:00～12:00」）。終わりが始まりより前なら終了時刻を入れず、
  その旨を note に書く
- 名称は空白を全部落とす（日本語の名称に本来の空白は無い。折り返しで入っただけ）
- **「盆踊り」だけの名前が 8 件ある。** 実施団体（町会名）を前に付けないと区別できない。
  ただし「亀戸２丁目町会」と「亀戸二丁目町会夏まつり」のように**同じ町名を
  全角数字と漢数字で書き分ける**ので、数字を揃えてから比べること
- **区の一覧ページの URL は 404 だった**（PDF だけが生きている）。出典は PDF の URL にした

## 直っていない不具合（このデータ全体の問題）

**`data/areas/nationwide.yml` の slug が 135 組で重複している。**
`aichi-006` に刈谷市と名古屋市名東区、`osaka-002` に高槻市・天王寺区・福島区・守口市。

複数の取り込みが独立に連番を振るので `osaka-001` が何度も作られる。

直すには slug の振り直しと**ファイルの移動**が要る（URL が変わる）。
今回は既存データに触らない約束なので記録だけ。`gotouti.mjs` の `create()` は
使用済み slug を確かめてから振っている。

**関東 7 都県は `writeNationwideAreas` が「手で整えた県」として弾く**ので、
新しい市区町村を足しても area 定義に載らない。
`tokyo/hachioji`・`chiba/urayasu` を含む **76 のディレクトリに area 定義が無い**。

### 行政の PDF を読む

行政の祭り一覧は PDF 公開が多く、しかも**権限制限がかかっていて WebFetch でも
Read ツールでも中身が取れない**（「password-protected」と出る）。
ユーザーパスワードは空で閲覧制限だけなので、pdfjs にその旨を渡せば読める。

```bash
node scripts/crawl/pdf-text.mjs <file.pdf>
```

y 座標でグループ化して表の行に戻すので、そのまま一覧として読める。
これで葛飾区（52 件）と江戸川区中央地区（23 件）が取れた。

### 町会いんふぉ（chokai.info）— 町内会が自分で書いた一次情報

町内会・自治会向けのホームページ作成サービス。**406 団体**が使っている。
新着情報の見出しが決まった形をしていて機械的に構造化できる。

```
納涼盆踊り大会（令和8年8月2日）［五反野西町会］／足立区
```

角括弧が主催団体、スラッシュ以降が市区町村。**出典の格は最上位（official）**。

```bash
node scripts/crawl/chokai-info.mjs
```

robots.txt で **8 つの町内会が明示的にクロールを拒否**しているので、
クローラはその Disallow を読んで該当ディレクトリに一切アクセスしない。

**結果: 322 見出しのうち 290 が既存データと重複**した。つまり町会いんふぉの内容は、
区が公式に出している一覧とほぼ重なる。新規は 33 件。
「一次情報だから新しい情報が取れる」わけではなく、**同じ情報を別ルートで裏取りできる**
という価値のほうが大きかった（区公式データとの突合が取れた）。

注意点:
- 角括弧は全角［］と半角[] の両方が使われている
- 2026 年の告知がまだ出ていない団体が多い。前年の実績も拾い「2025年の情報です」と明示

### enrich で潰したバグ（2026-08-05）

- **`patch()` のリンクが毎回積み上がっていた**。`uniq()` は Set なので
  `{title,url}` の重複を落とせない（別のオブジェクトは常に別物扱い）。
  enrich を流すたびに同じリンクが増え、1 件に 15 本並んでいた（76 件）。
  **URL をキーにして重ねる**よう直した。素の文字列と `{title,url}` が
  同じ URL を指していたら題のある方を残す
- **`import/mypl.mjs` が引数必須で終了コード 1 を返し、`npm run collect` が
  そこで止まっていた**。ファイル名順に流すので、m より後ろの
  nakahara・nerima・ota・rarea・setagaya… がまるごと動いていなかった。
  引数なしのときは取得済みの地域を順に処理する（これで 88 件増えた）
- **神社庁の社号に神社IDが付いたまま入っていることがある**（「皇大神宮 1206021000」）。
  社号が一致せず、その神社だけ住所を入れられない

### この工程で潰したバグ

- **東京が 548 社中 75 件しか入らなかった**。インポータの住所分解が東京の特別区
  （前に市がつかない「◯◯区」）に対応しておらず、472 社が丸ごと弾かれていた → 492 件に
- **同じ区の同名神社が消えていた**。重複判定のキーが「市区町村＋神社名＋種別」だったため、
  大田区の稲荷神社のように同名の神社が並ぶと 2 社目以降が全部落ちた。
  神社庁由来のファイルは重複判定の対象から外し、手入力データの保護だけに使うよう変更
- **`gen-areas` が自分の出力を読んでいた**。実行のたびに市町村が減っていた
- **埼玉パーサが「御祭神」の行を拾っていた**（`th.includes('祭')` が誤爆）。
  祭神名を日付として解釈していたぶんをキャッシュから削除し再取得
- **「7月最終金・土・日曜」が 7/25・7/26・7/31 とバラけていた**。曜日ごとに独立して
  「月内最後の◯曜」を取っていたため。最後の金曜から連続 3 日と読むよう修正

**神奈川と埼玉・東京の差、さらにその他4県との差は、祭りの多寡ではなく情報公開の差。**
千葉・茨城・栃木・群馬は神社庁が神社データベースを持っていないため、
1件ずつ手で積むしかない。


町内会レベルの祭りは、まとめサイトを追いかけても集まらない。
**各都県の神社庁が県内全神社の例祭日を公開している**ので、そこを機械的に舐めるのが本線。
まとめサイト・地域メディアは、そこに肉付けする補助線として使う。

## パイプライン

```
crawl（神社庁を巡回）→ gen-areas（市区町村の定義を生成）→ import（祭りデータ化）
  → enrich（一次情報で裏取り）→ validate（門番）→ build
```

```bash
node scripts/crawl/jinjacho.mjs <pref>
```

```bash
npm run collect
```

クロールはディスクキャッシュを持つので、中断してもやり直しにならない。
1リクエストごとに 700ms あけ、User-Agent で素性を名乗り、公開サイトマップからのみ辿る。

```
Content-Signal: search=yes, ai-train=no, use=reference
```

と明示されていた。ai-train は拒否、use は reference まで。ここから一括で抽出して
自分のサイトのデータベースにするのは reference の範囲を超える。加えて yaokami 自体が
神社庁データの集約サイトであって一次情報ではない。**このプロジェクトの「一次情報まで遡る」
という方針とも合わないので、使わない。**

### 千葉・茨城・栃木・群馬をどう埋めるか

神社庁が使えない以上、横浜・川崎でやったのと同じ手作業に戻る。

1. 各神社の公式サイト（香取神宮・鹿島神宮・日光二荒山神社・貫前神社などは自前のサイトを持つ）
2. 市町村の観光協会・行政ページ
3. 地域メディア（号外NET・タウンニュースは関東の広い範囲に版がある）

数は稼げないが、出典の格は上がる。

新しい都県を足す手順:

1. robots.txt とサイトマップを確認する
2. `scripts/crawl/jinjacho.mjs` の `ADAPTERS` に 1 件足す（`base` / `sitemaps` / `accept` / `id` / `parse`）
3. `scripts/lib/romaji.mjs` にその都県の市区町村 slug を足す
4. `scripts/gen-areas.mjs` の `PREF` に足す
5. `npm run collect`

## 日付ルールの解決

神社庁は日付をルールで持っている（`10月第1日曜日`／`9月15日に近い日曜日`／`体育の日`）。
`scripts/lib/jpdate.mjs` がこれを指定年の実日付に落とす。対応済みの書式:

- `N月D日`、`N月D日〜D日`、`N月D日〜N月D日`
- `N月第K◯曜日`（漢数字・全角数字とも）、`N月第K土・日曜日`
- `N月最終◯曜日`
- `N月D日に近い◯曜日`
- 祝日名（海の日・スポーツの日・敬老の日など、ハッピーマンデーを含む）

**ルールから導いた日付は必ず `status: estimated`** にする。神社が今年の日程として
発表したわけではないので、個別ページにもその旨が出る。

## 取り込みの方針

- 参拝者が集まる祭りだけ入れる。月次祭・大祓・祈年祭・新嘗祭・歳旦祭・節分祭のような
  全神社にある内向きの祭祀は、数だけ膨らんで祭り探しの邪魔になるので入れない
- 同じ市区町村・同じ神社・同じ種別の祭りが既にあれば飛ばす（手で入れたデータを守る）
- slug が `romaji.mjs` にない市区町村は取り込まず警告を出す。当て字の slug を勝手に
  作ると、あとから直せなくなる
